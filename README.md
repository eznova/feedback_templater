# Runtime

http://127.0.0.1:18500/

# Setup

Код приложения находится в пакете `src/`: модули Python, `src/templates/`
и `src/assets/`. Документация и тесты остаются в `docs/` и `tests/`.
Команды ниже выполняются из корня проекта; рабочая SQLite остаётся в `instance/`.

### Install requirements
```
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

### Run from cli
```
.venv/bin/python -m src.app
```

### Pack to Windows application
```
.venv/bin/python -m PyInstaller --onefile --paths . --add-data "src/templates:templates" --add-data "src/assets:src/assets" src/app.py
```

# Docker

Сборка и запуск одной командой:

```bash
./scripts/build-and-run.sh
```

Скрипт работает из любого каталога: сначала выполняет `git pull --ff-only`
в каталоге проекта для текущей ветки из её upstream, затем проверяет Docker/Compose, собирает образ,
создаёт сеть `moc`, если её нет, и пересоздаёт сервис в фоне. Данные в `instance/`
сохраняются. При ошибке Git (включая конфликт, расхождение истории или отсутствие
upstream) либо сборки скрипт останавливается до пересоздания контейнера.
Локальные правки автоматически не сбрасываются. Нужны Git, доступ к remote
и Docker daemon. Для d/raci upstream — origin/d/raci.
Скрипт использует Compose и `.env` проекта. Compose публикует порт `5081` хоста
на порт `18500` контейнера: http://127.0.0.1:5081/
(панель администратора — http://127.0.0.1:5081/admin).

Проверенная сборка отдельного образа:

```bash
docker build -t feedback_templater:build-check .
```

Compose содержит `build: .` и `image: feedback_templater`.
Для обновления существующего сервиса после переключения на `d/raci`:

```bash
docker compose up -d --build --force-recreate feedback_templater
```

У старой версии Docker Compose команда начинается с `docker-compose`.
Команда пересобирает образ из текущей ветки: запускается `src.app` на 18500,
а сайт доступен на порту хоста 5081. Если в логах `app` на 5000,
работает старый образ main: его нужно пересобрать, одного перезапуска недостаточно.
Каталог `instance` при обновлении сохраняется.

При необходимости отдельно собрать тег `feedback_templater`:

```bash
docker build -t feedback_templater .
```

`.dockerignore` исключает локальную SQLite, ключ сессий, `.env`, venv и кэши.
В чистом контейнере данные инициализируются заново; администратора нужно создать
через `flask --app src.app set-admin`. Compose монтирует `./instance` хоста
в `/app/instance` контейнера: база, ключ сессий и backup сохраняются при пересоздании.
Исходный код берётся из образа. Используется внешняя сеть `moc`;
её наличие требуется для запуска через Compose.

# Панель администратора

Адрес: http://127.0.0.1:18500/admin. Панель редактирует начальные значения
12 многострочных полей RACI. Пустые значения допустимы. Сохранение применяется
при следующем открытии публичной формы; ввод посетителей базу не изменяет.

Создать администратора или сменить его логин и пароль (пароль вводится скрыто,
не менее 12 символов):

```bash
.venv/bin/python -m flask --app src.app set-admin --username admin
```

Учётная запись одна. Смена пароля отзывает предыдущие сессии. После пяти
неудачных входов вход блокируется на пять минут; CLI-команда также сбрасывает блокировку.

SQLite: `instance/app.sqlite3` (таблицы `texts`, `admins`, `db_meta`). Начальные значения
создаются только для отсутствующих ключей и не затирают сохранённые тексты.
Пароль хранится в виде хеша scrypt. Ключ сессий автоматически создаётся
в `instance/session.key`; при необходимости его можно задать переменной `SECRET_KEY`.
Каталог `instance/` исключён из Git и Docker-образа, сохраняется отдельным bind mount.

Перед каждой записью приложения в существующую базу автоматически создаётся
согласованная копия SQLite в `instance/backups/`. Это относится к текстам, импорту,
смене администратора, счётчикам неудачных входов и миграциям.
Если копия не создана, изменение отменяется. Backup содержит состояние до записи;
при ошибке самой записи изменения откатываются. Хранятся последние 20 копий:
после создания новой и при запуске приложения старые удаляются по времени изменения файла.
Текущая БД и посторонние файлы не удаляются.
Имена включают время UTC, схему `sN`, ревизию `rN` и причину сохранения.

Админка показывает версию схемы (`PRAGMA user_version`, сейчас 1), ревизию данных
и время последней записи. При успешной записи ревизия увеличивается.
Рядом показана дата изменения файла текущей SQLite. В раскрывающемся списке
«Резервные копии» отображаются схема/ревизия, дата файла (МСК) и имя каждой копии,
от новых к старым. Дата файла берётся из файловой системы; при использовании WAL
она может отличаться от времени последней записи в метаданных.
У каждой копии есть кнопки «Скачать» (полный файл SQLite) и «Восстановить тексты».
Восстановление после подтверждения заменяет только 12 текстов RACI, сохраняет
логин/пароль/сессию, создаёт backup текущего состояния и увеличивает текущую ревизию.
Самая старая копия также восстанавливается: её содержимое читается до очистки истории.
Удалённая или повреждённая версия отклоняется без замены текстов.
Пустая база начинается с ревизии 1; старая база без версии автоматически
мигрируется с предварительной копией. Повторный запуск ревизию не изменяет.

В разделе «Импорт текстов из базы» можно загрузить SQLite размером до 32 МиБ.
Файл проверяется на целостность, совместимую схему (0 или 1) и 12 ключей RACI.
Импорт заменяет только тексты одной транзакцией с предварительным backup;
логин, пароль и текущая сессия сохраняются. Ревизия текущей базы увеличивается,
а не копируется из файла. Некорректный файл не меняет базу.

Кнопка «Скачать текущую БД» в админке скачивает согласованный полный снимок
SQLite: тексты, учётную запись администратора (с хешем пароля) и метаданные.
Имя — `raci-database-s<схема>-r<ревизия>.sqlite3`. Скачивание доступно только
после входа, не кэшируется и не изменяет ревизию или список backup.
Снимок подходит для обратного импорта текстов через ту же панель.

Резервную копию SQLite можно сделать без остановки приложения:

```bash
.venv/bin/python -c "import sqlite3; source = sqlite3.connect('instance/app.sqlite3'); target = sqlite3.connect('instance/backup.sqlite3'); source.backup(target); target.close(); source.close()"
```

Для восстановления остановить сервер, заменить `instance/app.sqlite3` копией
и запустить снова. Для сохранения действующих сессий сохранить также `session.key`.
Ручные изменения SQLite вне приложения обходят автоматические копии и ревизии;
перед ними резервную копию нужно создать самостоятельно.

Проверки панели на временной базе:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

# Отчёт и PDF матрицы RACI

Основная кнопка «Сгенерировать отчет» открывает HTML-документ на странице
в оформлении отчёта встреч. Выбранные разделы, адресат и текущие тексты
попадают в отчёт; переносы строк сохраняются, длинный текст не обрезается.
Шрифт Inter загружается из локальных файлов. Отчёт в базе не сохраняется.
Кнопка «Сгенерировать PDF» скачивает отдельный документ.


Выбрать «Матрица RACI», указать подразделение, заполнить поля и нажать
«Сгенерировать PDF». Короткий документ `raci.pdf` содержит шесть страниц A4:
оба вводных раздела без цветной подложки на первой, затем каждый из пяти процессов
начинается с новой страницы. Длинные тексты продолжаются на дополнительных страницах.
Адресат отображается на каждой странице согласно селекту;
«Не отображать» убирает плашку.

Используется ReportLab и включённые в `src/assets/fonts/` шрифты Inter 4.1 Regular и Bold
с кириллицей из официального релиза https://github.com/rsms/inter/releases/tag/v4.1
(лицензия SIL OFL 1.1 в `Inter-LICENSE.txt`). Шрифты встраиваются в PDF;
системные шрифты и браузер для генерации не нужны.
PDF создаётся в памяти из текущего ввода и не сохраняется в SQLite.
Начальные тексты по-прежнему редактируются в панели администратора.
В строке названия каждого из семи разделов есть чекбокс, включённый по умолчанию.
Снятие исключает весь раздел из HTML-отчёта и PDF, включая оба поля процесса и его страницы.
Введённый текст остаётся в форме. Если выключены оба вводных раздела,
документ начинается сразу с первого выбранного процесса.
Если выключены все разделы, форма просит выбрать хотя бы один.

Основной текст сохраняет размер 11 pt. Блоки делятся по строкам с учётом
доступной высоты страницы, без обрезки текста. На продолжении повторяются
общий заголовок, адресат, название раздела и подпись блока с пометкой «продолжение»;
цветная подложка сохраняется. Вводные тексты продолжаются без фона.
Прежнее ограничение 20 000 символов на поле снято.
Название подразделения обязательно (до 200 символов).

Общий цвет чекбоксов, целевых блоков и плашки адресата задаётся в `src/settings.py`:
по умолчанию `#DBD2FF`. Переопределение — переменная `RACI_ACCENT_COLOR`
в формате `#RRGGBB`. Compose передаёт её из окружения, не задавая своего значения;
отсутствующая или пустая переменная использует цвет из кода.
Некорректное значение останавливает запуск с пояснением.

Пример переопределения в `.env` рядом с Compose:

```dotenv
RACI_ACCENT_COLOR="#C8BAFF"
```

Затем пересоздать контейнер: `docker compose up -d --force-recreate`.
При запуске без Docker переменную передать процессу Flask и перезапустить сервер.

Тесты PDF включены в общую команду выше. Для проверки извлечения текста
нужен `pdftotext` (Poppler); при его отсутствии этот тест пропускается.

Тест большого документа заполняет все 12 полей одновременно ровно 100 000
символов каждое (1,2 млн суммарно), проверяет перенос каждого блока и точное
совпадение всего текста после извлечения. Рабочая SQLite не используется.
Тест требует `pdftotext`; при его отсутствии пропускается.

Последний проверенный результат: 567 страниц, около минуты на выполнение.

Отдельный запуск:

```bash
.venv/bin/python -m unittest discover -s tests -p test_pdf_stress.py -v
```

## Работа без интернета

Формы и панель администратора используют локальный Bootstrap 5.3.2
из `src/assets/bootstrap.min.css` (лицензия MIT рядом). Шрифты Inter
также поставляются с приложением. Браузеру и запущенному приложению
доступ в интернет не требуется; ресурсы включены в Docker-образ.
Первичная установка зависимостей и сборка образа могут требовать интернет.
