## Назначение и файлы

Python 3.12 + Flask + Jinja2 + SQLite + ReportLab.
Генератор обратной связи по встрече, HTML-отчёта и PDF матрицы RACI. Пользовательские отчёты не хранятся.

- `src/app.py`: GET /, POST /ft_generate (HTML встречи), POST /raci_generate (PDF по умолчанию, output=html — HTML).
- `src/templates/form.html`: выбор «Встречи» / «Матрица RACI», JS-скачивание PDF.
- `src/templates/raci_form.html`: подразделение, адресат, 7 разделов, 12 textarea;
  7 включённых чекбоксов в заголовках. Снятый раздел исключается целиком, ввод сохраняется.
- `src/raci_pdf.py`: `PdfLayout`, переносы через Paragraph.split, встроенный Inter 4.1
  Regular/Bold из `src/assets/fonts/` (SIL OFL). Основной текст 11 pt, без обрезки и лимита 20 000.
- `src/settings.py`: `RACI_ACCENT_COLOR` для CSS и PDF, по умолчанию `#DBD2FF`;
  env `#RRGGBB`, пустая/отсутствующая — цвет из кода, неверная — ошибка запуска.
- `src/admin.py`: логин, редактор 12 текстов, POST /admin/import, GET /admin/download,
  выход и CLI set-admin.
- `src/database.py`: SQLite, backup, миграция, ревизии, проверка импортируемого файла.
- `tests/test_admin.py`, `tests/test_raci_pdf.py`, `tests/test_pdf_stress.py`: проверки.

## SQLite и админка

`instance/app.sqlite3`: texts, admins, db_meta. Схема `PRAGMA user_version=1`.
Ревизия данных и время UTC в db_meta, отображаются в админке. Увеличиваются при записи.
Ключ сессий — `instance/session.key` (либо SECRET_KEY из env).
Учётная запись admin создана ранее; пароль в контексте не хранится.
Смена: `.venv/bin/python -m flask --app src.app set-admin --username admin`.
Пароль — scrypt, CSRF для всех POST панели; смена пароля отзывает сессии.
Пять неудачных входов блокируют вход на 5 минут.

Все записи существующей базы — через `database_change`: BEGIN IMMEDIATE,
backup отдельным SQLite-читателем до изменения, транзакция и новая ревизия.
Ошибка backup отменяет запись. Это включает счётчики входа и смену администратора.
Backup: `instance/backups/<UTC>-s<схема>-r<ревизия>-<причина>-<ID>.sqlite3`.
По REQ-0024 хранятся последние 20 копий по mtime, очистка после успешного backup
и при запуске. Текущая БД/посторонние файлы не удаляются, новая копия сохраняется.
Админка показывает дату текущего файла и историю: схема/ревизия, mtime (МСК), имя.
По REQ-0027 у каждой копии есть скачать полный файл и восстановить только тексты
RACI с подтверждением. GET /admin/backups/<filename>/download,
POST /admin/backups/<filename>/restore: вход, CSRF для POST, no-store.
Снимок читается до нового backup, поэтому самая старая из 20 тоже восстанавливается.
Восстановление сохраняет администратора/сессию, делает backup текущего состояния,
увеличивает текущую ревизию. Валидация схем 0/1 и текстов общая с импортом,
для локальной копии нет лимита 32 МиБ загрузки. Сторонние пути/ссылки/недоступные
версии отклоняются. Рабочие данные автоматически не восстанавливались.
Время последней записи из db_meta показано отдельно, оно может отличаться от mtime при WAL.
Прямой SQL вне приложения обходит механизм backup/ревизий.
Новая база начинается с ревизии 1; старая схема 0 мигрируется с backup,
повторная инициализация не меняет ревизию и тексты; новая неподдерживаемая схема отклоняется.
Рабочая база мигрирована: схема 1, после миграции ревизия 1; текущую ревизию читать из БД.
Копия до миграции: `instance/backups/20261022T214640990821Z-s0-r0-before-migration-7f05ff3a.sqlite3`.

Импорт /admin/import: только 12 текстов RACI, без смены логина/пароля/сессии.
SQLite до 32 МиБ, проверка целостности, схемы 0/1 и ключей; backup перед заменой,
локальная ревизия увеличивается. Схема из файла не исполняется.

По REQ-0022 кнопка «Скачать текущую БД» выдаёт согласованный полный снимок
SQLite (включая администратора и метаданные), `raci-database-sN-rN.sqlite3`.
Backup API + serialize в памяти, авторизация, no-store; ревизия/backup не меняются.
Почтовую отправку пользователь отменил, SMTP и очередь доставки не реализуются.
