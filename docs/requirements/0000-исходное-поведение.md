# REQ-0000 — Исходное поведение генератора обратной связи

- Дата: 2026-10-22 (Europe/Moscow).
- Статус: Зафиксировано по коду.
- Источник: `app.py`, `templates/form.html`, `templates/result.html`, конфигурация проекта.
- Связи: REQ-0001, REQ-0002.

## Требование и границы

Сохранить существующее поведение как исходную точку для следующих изменений.
Приложение формирует HTML-отчёт «Обратная связь по встрече с сотрудником».

| Область | Текущее поведение |
| --- | --- |
| Вход | `GET /` показывает русскоязычную форму |
| Генерация | `POST /ft_generate` возвращает HTML-отчёт |
| Тип встречи | Встреча 1, 2, 3 или 6 месяца; «Запрос» |
| Поля | Тип и дата встречи, наличие рисков, ФИО, общие впечатления, мотиваторы, значимые факторы, области внимания |
| Обязательность | Дата и ФИО обязательны средствами HTML-формы |
| Дата | Вход `ГГГГ-ММ-ДД`, отображение `ДД / ММ`; пустая дата даёт пустую строку |
| Текстовые блоки | Разделение по строкам, удаление пробелов по краям и пропуск пустых строк |
| Отчёт | Тип встречи, дата, риски, ФИО и четыре текстовых раздела; значимые факторы выводятся с маркерами |

Цвета оформления (HEX):

| Условие | Светлый | Основной | Фон значимых факторов |
| --- | --- | --- | --- |
| Название «запрос», без учёта регистра | `9FDEDE` | `28D7D7` | `B3E4E4` |
| Остальные названия | `AB83F5` | `844BEC` | `E4D5FF` |

Риск «обрати внимание» отображается цветом `FFC72E`, «есть риски» — `B93131`,
остальные значения — `76B48F`; сравнение без учёта регистра.

Форма использует Bootstrap 5.3.2 с CDN. Результат построен на табличной HTML-вёрстке
с встроенными стилями и медиазапросами. Хранение отчётов, авторизация, отправка почты
и экспорт отдельным файлом в текущем коде не реализованы.

## Критерии приёмки

- Форма и обработчик содержат указанные поля и маршруты.
- Преобразование даты, строк и цветов соответствует таблицам.
- Результат включает заполненные данные в соответствующие разделы.

## Результат и проверка

Поведение описано по чтению обработчика и обоих шаблонов; полная функциональная
проверка всех вариантов не выполнялась. Ранее проверен `GET /`: HTTP 200.
Некорректная непустая дата и отсутствие `meeting_name` могут приводить к ошибке
обработчика; отдельной серверной валидации нет. Это ограничения текущего состояния,
а не требования сохранить ошибки.
