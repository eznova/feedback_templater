# REQ-0021 — Резервирование, хранение, импорт и версия SQLite

- Дата: 2026-10-23 (Europe/Moscow).
- Статус: Выполнено.
- Источник: резервная копия перед изменением БД, проброс БД из Docker на хост,
  импорт в админке и отображение версии БД. Уточнение: импортировать только тексты RACI.
- Связи: расширяет REQ-0007, REQ-0020.

## Требование и границы

Уточнение REQ-0024: история ограничена последними 20 резервными копиями,
даты файлов и список версий отображаются в админке.

Перед каждой записью приложения в существующую БД создавать согласованный SQLite
backup в `instance/backups/`. Это включает сохранение текстов, импорт, смену
администратора, счётчики входа и миграцию. При ошибке backup отменять запись.
Первичная пустая база создаётся без бессодержательной копии.

Версия схемы — `PRAGMA user_version` (первая версионированная схема: 1).
Ревизия данных и время изменения — в таблице `db_meta`; ревизия увеличивается
при каждой успешной записи приложения. Показывать оба номера в админке.
Старую базу версии 0 мигрировать автоматически с предварительным backup.
Схему новее поддерживаемой не изменять и сообщать об ошибке.

Compose монтирует `./instance` хоста в `/app/instance` контейнера вместо всего
исходного каталога. Это сохраняет SQLite, ключ сессий и backup после пересоздания.

В панели добавить загрузку SQLite с CSRF и авторизацией. Принимать совместимые
базы версий 0 и 1, проверять целостность и точный набор 12 текстовых ключей.
Импортировать только тексты одной транзакцией; администратора, сессии и другие
данные текущей базы не заменять. Локальная ревизия увеличивается, версия из файла
её не сбрасывает. Невалидный файл отклонять без изменения данных. Лимит загрузки — 32 МиБ.

## Критерии приёмки

- Backup содержит состояние до записи; текущая БД — новое состояние и новую ревизию.
- Ошибка backup или транзакции не приводит к частично сохранённым данным.
- Старая БД мигрируется с сохранением текстов и администратора; повторный запуск не меняет ревизию.
- Админка показывает версию схемы и ревизию; импорт доступен только после входа с CSRF.
- Валидный импорт меняет 12 текстов, сохраняет учётную запись и её сессию, делает backup.
- Повреждённая, несовместимая или слишком большая база не импортируется.
- Compose проходит проверку, данные на хосте сохраняются после пересоздания контейнера.

## Результат и проверка

Добавлен `database.py`: блокировка `BEGIN IMMEDIATE`, согласованный backup отдельным
читателем перед изменением, транзакционная запись и увеличение ревизии. Backup
хранятся рядом с базой в `backups/`, имена содержат время UTC, схему, ревизию и причину.
Первичная схема 1 создаётся с `db_meta`; схема 0 мигрируется с копией.
Подключены все записи `admin.py`, добавлен `/admin/import`, форма загрузки и версия в панели.
Валидация импорта: SQLite header, quick_check, схема 0/1 и ровно 12 текстовых ключей;
загруженная схема не исполняется, администратор и сессия не импортируются.
README и AGENTS.md дополнены правилами работы с БД.

В Compose общий mount исходников заменён на `./instance:/app/instance`.

пересобран. В двух последовательно созданных и удалённых контейнерах на отдельном
