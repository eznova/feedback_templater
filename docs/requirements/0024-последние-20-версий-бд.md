# REQ-0024 — Последние 20 версий БД и даты файлов

- Дата: 2026-10-23 (Europe/Moscow).
- Статус: Выполнено.
- Источник: «хранить нужно последние 20 версий (на фронте нужно выводить дату изменения файла тоже)».
- Связи: уточняет хранение backup из REQ-0021.

## Требование и границы

В `instance/backups/` оставлять последние 20 резервных SQLite-снимков,
упорядоченных по времени изменения файла. После создания новой согласованной копии
удалять самые старые, сохраняя новую копию. При запуске также применять лимит
к существующей истории. Текущая база и посторонние файлы не удаляются.

В админке показывать дату изменения файла текущей SQLite и историю сохранённых
копий: версия схемы, ревизия, дата изменения и имя файла. Даты отображать
по московскому времени с обозначением МСК. Сохранить отдельную дату последней
записи из метаданных. Просмотр истории не меняет ревизию.

## Критерии приёмки

- Более 20 изменений оставляют ровно 20 последних backup, новая копия сохранена.
- Повторный запуск сокращает ранее накопленную историю до 20 без изменения текущей БД.
- Ошибка создания новой копии не удаляет старую историю.
- Админка показывает даты текущего файла и копий; список идёт от новых к старым.
- Посторонние файлы, тексты, администратор и текущая ревизия при очистке не меняются.

## Результат и проверка

В `src/database.py` добавлены BACKUP_LIMIT=20, очистка по mtime после завершения
новой копии и при запуске, получение дат файла текущей базы и истории копий.
Новая копия защищена от удаления, в очистку входят только обычные *.sqlite3
из backups/, посторонние файлы и символические ссылки не затрагиваются.
В админке добавлены дата файла текущей БД и раскрываемая таблица версий,
дат (МСК) и имён копий. Чтение истории не изменяет ревизию.
