# REQ-0039 — Проверка версии при обновлении скриптом

- Дата: 2026-10-23 (Europe/Moscow).
- Статус: В работе.
- Источник: в футере «Версия: неизвестен»; пользователь уточнил, что сборка выполнена через build_and_run.
- Связи: REQ-0036, REQ-0037.

## Требование и границы

Проверить передачу APP_COMMIT через скрипт и обеспечить выполнение обновлённой
версии скрипта после git pull, если тот изменился. Проверять APP_COMMIT
запущенного контейнера относительно HEAD после обновления; при несовпадении
не сообщать успешный запуск. В логе явно печатать собираемый коммит.
Причина на другом хосте не доказана: возможен запуск старого скрипта,
обновляющего себя без повторного исполнения. Прямой Compose без APP_COMMIT
остаётся документированным сценарием, здесь проверяется запуск скриптом.

## Критерии приёмки

- После изменения скрипта при pull выполняется новая версия, без бесконечного цикла.
- Хеш фиксируется после pull, передаётся сборке и проверяется в контейнере.
- Сбой pull, сборки или проверки версии возвращает ошибку.
- Проверены сценарии подмены команд и реальная сборка/футер; правки опубликованы в d/raci.

## Результат и проверка

Основная часть скрипта обёрнута в функцию: Bash загружает её целиком до pull.
Содержимое скрипта до/после pull сравнивается, при изменении exec запускает
новую версию. APP_COMMIT вычисляется отдельной командой, ошибка Git больше
не скрывается export. Хеш печатается перед сборкой, после compose up проверяются
APP_COMMIT и commit_hash() в контейнере; при ошибке успех не сообщается.
README содержит инструкцию первичного обновления старого скрипта.

bash -n и 7 сценариев с подменой Git/Docker прошли: успех, ошибка pull,
ошибка rev-parse, ошибка build, ошибка проверки версии, самообновление,
--help. Проверены два pull и одна сборка при обновлении скрипта.
Локально исходный путь сборки передавал хеш правильно; точная причина на хосте
пользователя без его файлов и метаданных не установлена.
Реальная сборка закоммиченной версии и публикация выполняются далее.
