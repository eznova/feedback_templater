# Правила работы ИИ с проектом

## Начало работы

1. Прочитать `docs/CONTEXT.md` и реестр `docs/requirements/README.md`.
2. Открыть только относящиеся к задаче требования и участки кода.
3. Проверить фактическое состояние нужных файлов и процессов: контекст может устареть.

## Подход AI-first

- Каждый следующий запрос пользователя сначала записывать отдельным файлом
  `docs/requirements/NNNN-краткое-название.md` по `docs/requirements/TEMPLATE.md`.
  Номер — следующий свободный в реестре. Уточнение связывать с исходным требованием.
- Требования, решения, критерии приёмки и контекст писать на русском языке.
- Сначала зафиксировать запрос, границы и проверяемые критерии, затем выполнять работу.
  Не придумывать пожелания пользователя; предположения обозначать явно.
- Для вопроса или исследования результатом может быть ответ или вывод, без изменения кода.
- Противоречащее старому новое требование связывать с ним; старое помечать
  «Заменено REQ-NNNN», сохраняя историю.
- После работы записывать результат, затронутые файлы, выполненные проверки и ограничения;
  обновлять статус и реестр. Не считать непроверенное проверенным.
- Обновлять `docs/CONTEXT.md` при изменении поведения, запуска, решений или незавершённых задач.
  Хранить там краткое актуальное резюме и ссылки, а подробности — в требованиях.
- Завершая задачу, кратко сообщать результат и ссылку на требование.

## Технические ориентиры

- Python, Flask, Jinja2; приложение `src/app.py`, шаблоны в `src/templates/`.
- Локальная среда — `.venv`, текущий порт — `18500`.
- Для запуска без отладки: `.venv/bin/python -m flask --app src.app run --host 0.0.0.0 --port 18500`.
- Проверки выбирать по изменению. Для документации достаточно проверить ссылки и согласованность;
  для поведения — соответствующие сценарии. Не менять поведение ради описания текущего состояния.
- Не включать секреты, содержимое venv и временные журналы в документацию или коммиты.
- Все изменения существующей SQLite выполнять через `src.database.database_change`:
  он делает backup до записи и увеличивает ревизию после успешной транзакции.
  Изменение схемы проводить миграцией с backup и обновлением `PRAGMA user_version`.
